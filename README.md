## Layer Summary

### Bronze

Bronze preserves raw-ish external observations and collection lineage.

- `01a_bronze_fred_bootstrap_versions.py` performs the initial ALFRED-capable revision-history load.
- `01b_bronze_fred_incremental_versions.py` performs incremental ALFRED vintage-date checks and loads changed revision windows.
- `01c_bronze_fred_current_observations.py` handles FRED current-only observations and stores canonical FRED metadata such as units, frequency, and seasonal adjustment.
- `01d_bronze_macrotrends_observations.py` loads manually downloaded Macrotrends bootstrap history into the current-observation raw table, currently for `BAMLH0A0HYM2`.
- `01e_bronze_alfred_reproducibility_audit.py` compares internal point-in-time reconstruction against live ALFRED `vintage_dates` API responses for selected as-of dates.
- `01f_bronze_yahoo_finance_observations.py` loads Yahoo Finance bootstrap history into the current-observation raw table, currently for `SP500` via `^GSPC`.

The seed catalog lives at `notebooks/databricks/configs/fred_seed_series.json`. The generated metadata catalog `fred_series_metadata.json` is built from the FRED API and supplies canonical units/frequency metadata for Macrotrends and Yahoo bootstrap loaders.

```text
alfred_available = true   -> bronze/01a + bronze/01b
alfred_available = false  -> bronze/01c current refresh
external bootstrap gaps   -> configs/build_fred_series_metadata.py, then bronze/01d or bronze/01f, then bronze/01c for later FRED refreshes
```

### Silver

Silver cleans and conforms Bronze tables into two analytic inputs:

- `fred_observation_versions_cleaned` for ALFRED revision-aware point-in-time rows.
- `fred_current_observations_cleaned` for FRED current-only rows, including bootstrap rows sourced from Macrotrends or Yahoo Finance.

Current-only Silver preserves source metadata columns such as `units`, `units_short`, `frequency`, `frequency_short`, `seasonal_adjustment`, and `seasonal_adjustment_short` so Gold can carry source semantics into transformed features.

### Gold

Gold starts with the as-of feature mart in `03_gold_fred_asof_features.py`.

It integrates ALFRED revision-aware rows and FRED current-only rows, applies an optional analysis window, creates period-level features, and emits common transformation rows. The primary dashboard table is `fred_transformed_features_long`.

Gold also includes `03b_gold_lagged_correlation_analysis.py`, which computes lagged Pearson correlation scores for EDA and dashboard ranking. These scores are not used as causal-inference evidence or as a causal variable-selection gate.

The previous 04 causal-inference notebooks were removed because their assumptions, especially no unobserved confounding, cannot be justified from the collected dataset alone.

## Typical Execution

```text
Initial build:
1. configs/build_fred_series_metadata.py
2. bronze/01a_bronze_fred_bootstrap_versions.py
3. bronze/01d_bronze_macrotrends_observations.py when Macrotrends bootstrap history is needed
4. bronze/01f_bronze_yahoo_finance_observations.py when Yahoo Finance bootstrap history is needed
5. bronze/01c_bronze_fred_current_observations.py for FRED current-only rows and later refreshes
6. bronze/01e_bronze_alfred_reproducibility_audit.py for ALFRED point-in-time spot checks
7. silver/02a_silver_fred_bootstrap_versions.py
8. silver/02c_silver_fred_current_observations.py
9. gold/03_gold_fred_asof_features.py
10. gold/03b_gold_lagged_correlation_analysis.py when lagged correlation analysis is needed

Refresh workflow:
1. configs/build_fred_series_metadata.py when seed metadata changes
2. bronze/01b_bronze_fred_incremental_versions.py
3. bronze/01c_bronze_fred_current_observations.py
4. bronze/01e_bronze_alfred_reproducibility_audit.py for scheduled sample as-of dates
5. silver/02b_silver_fred_incremental_versions.py
6. silver/02c_silver_fred_current_observations.py
7. gold/03_gold_fred_asof_features.py with the desired as_of_date and analysis window
8. Re-run 03b only when downstream lagged correlation rankings should be refreshed
```
